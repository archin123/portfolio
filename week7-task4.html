1. Objective & Problem Statement

Problem Being Addressed: Standalone IoT prototypes that only display sensor readings on local LCD screens or serial terminals fail to deliver value when operators are off-site. Furthermore, exposing raw microcontroller endpoints directly to the public internet creates severe cybersecurity vulnerabilities, including Denial-of-Service attacks, unauthorized relay actuation, and lack of accountability.

Objective: Develop a secure, cloud-hosted IoT monitoring dashboard that leverages Google Firebase to provide:

  • Secure User Authentication ensuring only authorized operators (arch@gmail.com) can access controls.
  • Real-time telemetry display of ambient temperature, humidity, and light intensity (LDR).
  • Bidirectional control of appliances (Bulb ON/OFF) with operating mode selection (Manual vs Automatic).

2. Cloud Computing Fundamentals & Service Models

Cloud Computing refers to the on-demand availability of computer system resources—especially data storage (cloud storage) and computing power—without direct active management by the user.

Model Full Meaning Management Scope Industry Example & Role in IoT
IaaS Infrastructure as a Service Rents physical or virtual servers, networking, and raw storage. User manages OS, runtimes, and apps. AWS EC2, Google Compute Engine. Used for heavy custom IoT time-series clusters.
PaaS Platform as a Service Provides hardware and an application-software platform (runtimes, databases). User only deploys code. Google App Engine, Heroku. Used to host scalable microservices.
SaaS Software as a Service End-user applications accessible over the internet via browser or client. Fully managed by vendor. Google Drive, Slack, Adafruit IO Web Dashboard.
BaaS Backend as a Service Provides ready-to-use backend cloud services via client-side SDKs (Auth, Realtime DB, Cloud Storage). Google Firebase — Eliminates writing custom server middleware for this dashboard.

Key Definitions

  • Cloud Platform: An integrated ecosystem of cloud services (compute, storage, identity, analytics) hosted on enterprise data centers that allows developers to build, run, and scale applications globally.
  • Database: An organized collection of structured or semi-structured data stored electronically in a computer system, managed by a Database Management System (DBMS).
  • Firebase Realtime Database: A cloud-hosted NoSQL database where data is stored as a massive JSON tree. Clients (browsers and ESP32s) establish a persistent bi-directional WebSocket connection, synchronizing data updates in milliseconds across all devices without polling.
  • Cloud-Based Dashboard: A responsive web interface that subscribes to cloud database endpoints and translates incoming JSON telemetry streams into visual indicators, charts, and control switches.

4. Security: Authentication vs Authorization

Security in an IoT cloud architecture requires strict boundaries between verifying identity and granting resource permissions:

Security Domain Authentication (AuthN) Authorization (AuthZ)
Core Question "Who are you?" "What are you permitted to do?"
Mechanism Validates credentials (Email & Password hash) via Firebase Auth. Enforces Realtime Database Security Rules on specific JSON nodes.
Implementation firebase.auth().signInWithEmailAndPassword(...) Database rules requiring auth != null to write to /control.
User Context Student signs in as arch@gmail.com with valid token. Only authenticated tokens can modify /control/bulb. Public writes denied.

Configured Firebase Security Rules

    "sensors": {
      ".read": true,
      ".write": "auth != null"
    },
    "control": {
      ".read": true,
      ".write": "auth != null"
    },

5. Complete Dashboard Source Code

The dashboard is implemented using vanilla HTML5, CSS3, and JavaScript with the Firebase JavaScript SDK. All files are fully stored and versioned in the repository:

code/task4_firebase_dashboard/app.js (Core Firebase Integration) Download app.js 
// Initialize Firebase with Project Configuration
const firebaseConfig = {
  apiKey: "AIzaSyYOUR_FIREBASE_API_KEY",
  authDomain: "esp32-iot-monitor-8d34d.firebaseapp.com",
  databaseURL: "https://esp32-iot-monitor-8d34d-default-rtdb.firebaseio.com",
  projectId: "esp32-iot-monitor-8d34d"
};
firebase.initializeApp(firebaseConfig);
const auth = firebase.auth();
const database = firebase.database();

// Observer for Authentication State
auth.onAuthStateChanged(user => {
  if (user) {
    document.getElementById("userEmailDisplay").textContent = user.email;
    document.getElementById("authContainer").style.display = "none";
    document.getElementById("dashboardContainer").style.display = "block";
    subscribeToDatabase();
  } else {
    document.getElementById("dashboardContainer").style.display = "none";
    document.getElementById("authContainer").style.display = "flex";
  }
});

// Live Database Subscription
function subscribeToDatabase() {
  database.ref("sensors").on("value", snapshot => {
    const data = snapshot.val();
    if (!data) return;
    document.getElementById("valTemp").textContent = data.temperature.toFixed(1);
    document.getElementById("valHumidity").textContent = data.humidity;
    document.getElementById("valLdr").textContent = data.ldr;
  });

  database.ref("control").on("value", snapshot => {
    const ctrl = snapshot.val();
    if (!ctrl) return;
    const bulbOn = (ctrl.bulb === true || ctrl.bulb === "true");
    document.getElementById("lblBulbState").textContent = bulbOn ? "ON" : "OFF";
    document.getElementById("lblCurrentMode").textContent = ctrl.mode || "manual";
  });
}

// Bulb Toggle Action
document.getElementById("btnBulbToggle").addEventListener("click", () => {
  const currentText = document.getElementById("lblBulbState").textContent;
  const nextState = (currentText !== "ON");
  database.ref("control").update({
    bulb: nextState,
    lastChanged: auth.currentUser ? auth.currentUser.email : "arch@gmail.com"
  });
});

8. Problems Encountered & Technical Solutions

Problem Encountered Technical Cause Engineering Solution
Permission Denied on Realtime Database write Database rules were locked with ".write": false by default. Updated security rules to allow writes when auth != null, requiring valid token authentication.
Cross-Origin Request Blocked (CORS) Local HTML file tested via file:// protocol encountered origin mismatch with Firebase Auth callbacks. Hosted dashboard on GitHub Pages and local HTTP web server environment.
Dashboard not updating when mode changed on device Dashboard previously used single-read once("value") instead of persistent listener on("value"). Refactored codebase to use reactive WebSocket event listeners that trigger automatic DOM updates.
Relay flickering during rapid browser button clicks Lack of debounce allowed multiple duplicate write packets to flood the database. Added UI button debouncing and disabled toggle button while in Automatic mode.

9. Learning Reflection

Developing this Firebase-powered IoT monitoring system provided deep insight into the power of Backend-as-a-Service (BaaS). By leveraging Firebase's managed Authentication and Realtime Database, I was able to build an enterprise-grade IoT platform with instant WebSocket data synchronization without having to maintain a custom Node.js/Python server backend.

Understanding the strict architectural boundary between Authentication (verifying arch@gmail.com) and Authorization (database read/write rules) was an invaluable cybersecurity lesson that directly enhanced the reliability of the system.
