1. Objective & Problem Statement

Problem Being Addressed: Traditional embedded microcontrollers require physical interaction (such as push-buttons or mechanical toggle switches) to control electrical loads. In smart buildings, industrial plants, and healthcare environments, physical contact is often inconvenient, hazardous, or impractical. There is a need for low-cost, wireless, platform-independent remote control without requiring proprietary mobile apps or dedicated display hardware.

Assignment Objective: Configure the ESP32 microcontroller as a self-hosted HTTP Web Server within a local 2.4 GHz Wi-Fi network. The server must dynamically serve a modern, mobile-responsive HTML/CSS control webpage to any client browser on the network and execute bidirectional digital pin actuation (switching an LED ON and OFF) based on incoming HTTP request endpoints.

2. ESP32 Web Server Architecture

The ESP32 features a dual-core Xtensa 32-bit LX6 microprocessor with integrated 802.11 b/g/n Wi-Fi and Bluetooth. When configured in Station (STA) Mode, the ESP32 connects to an existing Wi-Fi Access Point (router) and obtains a local private IP address (e.g., 10.136.159.233) via DHCP.

Using the Arduino core WebServer library, a lightweight HTTP daemon binds to TCP Port 80. The ESP32 continuously listens for incoming client TCP socket connections via server.handleClient(). When an HTTP client (browser) opens the ESP32 IP address, the server dispatches predefined callback routines mapped to specific URIs:

  • GET /: Compiles and returns the full HTML5/CSS3 control interface.
  • GET /on: Writes digital HIGH to the LED GPIO, updates internal state, and sends back the refreshed webpage with status indicator glowing green.
  • GET /off: Writes digital LOW to the LED GPIO, updates state, and sends back the webpage with status indicator gray/red.

3. Communication Protocol & Wi-Fi Packet Flow

The communication between the user's browser (client) and the ESP32 (server) follows the standard stateless Hypertext Transfer Protocol (HTTP/1.1) over a Wi-Fi TCP/IP socket:

1. Web Browser (Client Device) User navigates to http://10.136.159.233/ or clicks [ON] / [OFF]
Wi-Fi TCP Port 80↓
2. HTTP Request Transmission GET /on HTTP/1.1 | Host: 10.136.159.233 | Accept: text/html
DHCP Local Network↓
3. ESP32 Web Server (Station Mode) server.handleClient() matches route -> executes handleLEDOn()
GPIO Bus Signal↓
4. Physical Hardware Actuation digitalWrite(LED_PIN, HIGH) -> 3.3V applied to Anode
HTTP Response Packet↓
5. Browser Renders Updated UI HTTP/1.1 200 OK | Content-Type: text/html | Status: ON

5. Circuit Schematic & Pin Connections

The circuit utilizes GPIO 2 (or GPIO 4) configured as OUTPUT. The current-limiting resistor is calculated using Ohm's Law:
R = (V_ESP32 - V_LED) / I_LED = (3.3V - 2.0V) / 0.010A = 130 Ω. A standard 220 Ω resistor guarantees a safe, stable current of approximately 6 mA, well below the ESP32 pin maximum of 12 mA.

6. Complete Arduino Source Code

The complete, verified Arduino C++ sketch. Includes Wi-Fi association, HTTP route registration, HTML generation with embedded CSS, and non-blocking client handling:

code/task1_esp32_web_server/task1_esp32_web_server.ino Download .ino 
#include <WiFi.h>
#include <WebServer.h>

const char* ssid     = "YOUR_WIFI_SSID";
const char* password = "YOUR_WIFI_PASSWORD";

const int LED_PIN = 2; // Onboard LED or external LED on GPIO 2/4
bool ledState = false;

WebServer server(80); // HTTP Port 80

String generateWebpage() {
  String page = "<!DOCTYPE html><html lang='en'><head><meta charset='UTF-8'>";
  page += "<meta name='viewport' content='width=device-width, initial-scale=1.0'>";
  page += "<title>ESP32 LED Control - Wi-Fi Web Server</title>";
  page += "<style>body{background:#1e2430;color:#fff;font-family:sans-serif;display:flex;align-items:center;justify-content:center;min-height:100vh;margin:0;}";
  page += ".card{background:#2b3445;padding:36px;border-radius:20px;text-align:center;box-shadow:0 15px 35px rgba(0,0,0,0.4);max-width:340px;width:100%;}";
  page += ".indicator{width:80px;height:80px;border-radius:50%;margin:20px auto;";
  page += ledState ? "background:#22c55e;box-shadow:0 0 25px #22c55e;}" : "background:#475569;}";
  page += ".btn{padding:12px 24px;border-radius:10px;color:#fff;text-decoration:none;font-weight:700;margin:0 6px;display:inline-block;}";
  page += ".btn-on{background:#22c55e;}.btn-off{background:#ef4444;}</style></head>";
  page += "<body><div class='card'><h1>ESP32 LED Control</h1><p style='color:#94a3b8;'>Wi-Fi Web Server</p>";
  page += "<div class='indicator'></div><p style='font-size:18px;margin-bottom:24px;'>LED Status: <strong>" + String(ledState ? "ON" : "OFF") + "</strong></p>";
  page += "<a href='/on' class='btn btn-on'>ON</a><a href='/off' class='btn btn-off'>OFF</a>";
  page += "</div></body></html>";
  return page;
}

void handleRoot() {
  server.send(200, "text/html", generateWebpage());
}

void handleLEDOn() {
  ledState = true;
  digitalWrite(LED_PIN, HIGH);
  Serial.println("[HTTP] Client requested /on -> LED pin set HIGH");
  server.send(200, "text/html", generateWebpage());
}

void handleLEDOff() {
  ledState = false;
  digitalWrite(LED_PIN, LOW);
  Serial.println("[HTTP] Client requested /off -> LED pin set LOW");
  server.send(200, "text/html", generateWebpage());
}

void setup() {
  Serial.begin(115200);
  pinMode(LED_PIN, OUTPUT);
  digitalWrite(LED_PIN, LOW);

  WiFi.mode(WIFI_STA);
  WiFi.begin(ssid, password);
  while (WiFi.status() != WL_CONNECTED) {
    delay(500);
    Serial.print(".");
  }

  Serial.println("\nWi-Fi Connected!");
  Serial.print("ESP32 IP Address: ");
  Serial.println(WiFi.localIP());

  server.on("/", HTTP_GET, handleRoot);
  server.on("/on", HTTP_GET, handleLEDOn);
  server.on("/off", HTTP_GET, handleLEDOff);
  server.begin();
  Serial.println("Web Server Started! Ready for browser commands.");
}

void loop() {
  server.handleClient();
  delay(2);
}

Detailed Code Section Breakdown

  • WiFi.mode(WIFI_STA): Configures the ESP32 in Station Mode, allowing it to connect to an existing WLAN without occupying Access Point mode overhead.
  • server.on("/on", HTTP_GET, handleLEDOn): Maps the URL endpoint /on to the handler function, ensuring that any HTTP GET request dispatched from the browser triggers immediate hardware pin toggling.
  • server.send(200, "text/html", generateWebpage()): Issues an HTTP Status Code 200 OK with MIME type text/html, delivering the dynamic UI markup back to the browser socket.
  • server.handleClient(): The non-blocking core execution function inside loop() that parses socket buffers and handles client connections.

7. Webpage Command Mechanism & Network Analysis

When the user clicks the green ON button on the webpage, the browser dispatches an asynchronous HTTP GET request to http://10.136.159.233/on. The Chrome DevTools Network inspection screenshot (task one 2.png) provides empirical evidence of this exchange:

HTTP Request Headers (Captured via DevTools):

Request Method: GET
Status Code: 200 OK
Remote Address: 10.136.159.233:80

The ESP32 receives the GET verb, matches the /on path, calls digitalWrite(LED_PIN, HIGH), updates its internal state variable ledState = true, and immediately replies with the refreshed HTML containing the glowing green circle.

10. Problems Encountered & Technical Solutions

Problem Faced Underlying Root Cause Implemented Solution
ESP32 could not associate with Wi-Fi network ESP32 only supports 2.4 GHz IEEE 802.11 b/g/n bands; failed when connecting to 5 GHz dual-band SSIDs. Separated the Wi-Fi router bands and connected exclusively to the dedicated 2.4 GHz SSID.
Webpage timed out (ERR_CONNECTION_TIMED_OUT) Client phone/laptop was connected to cellular data / different subnet from the ESP32. Connected both client and ESP32 to the identical AP subnet and confirmed ping to 10.136.159.233.
LED failed to turn on despite Serial Monitor indicating HIGH Wrong GPIO pin used or LED polarity inverted (anode/cathode reversed). Checked ESP32 DevKit pinout schematic, reconnected anode through 220Ω resistor to GPIO 2, and cathode to GND.
Server became unresponsive after multiple browser reloads TCP sockets remained hung due to omitted Connection: close header. Included standard HTTP/1.1 response headers and ensured server.handleClient() loops smoothly with a 2ms yield.
